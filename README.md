## 📖 So, what is this?

This roadmap is all about **how the backend actually works**, and how you can become a Django developer with a really solid understanding of what's going on under the hood (not just copy-pasting tutorials 😉).

### 🎯 By the end, you will have:

1. Learned backend **`fundamentals`**
2. Learned **`Django`**
3. Learned everything needed to work as a **`Junior Django Dev`**

### 🏆 Beginner Project: Library Management System (CLI)

_A terminal app that starts as simple functions and ends as clean, object-oriented code._

<details>
<summary><b>📝 Week 4: Python Basics (part 1)</b></summary>

```
Study: Python Basics (Osama Elzero 1 -> ~46)
(data types, strings, numbers, lists, tuples, dictionaries,
operators, if / else, membership)

1. Store at least 5 books in a dictionary:
   the key is the title, the value is another dictionary
   (author, year, is_available).
2. Ask the user for a book title using input() and check if it exists
   in your books using `in`.
3. If it exists, print its details in a nice format (f-strings)
   and tell the user if it's available or already borrowed.
4. If it doesn't exist, print a friendly message.
5. Print how many books you have, and the first 10 letters
   of the title the user searched for (string slicing).
```

</details>

<details>
<summary><b>📝 Week 5: Python Basics (part 2)</b></summary>


```
Study: Python Basics (Osama Elzero ~47 -> 80)
(loops, functions, built-in functions, modules)
 
1. Turn your week 4 script into a menu that keeps running (while loop):
   Add book, List books, Search book, Remove book, Exit.
2. Each menu action is its own function.
3. List the books using a for loop in a nice format.
4. Add Borrow & Return:
   a book can't be borrowed if it's already borrowed,
   and can't be returned if it isn't borrowed.
   Save the name of the person who borrowed it.
5. Use at least one module
   (e.g. `datetime` to save the borrow date,
   or move your functions to their own file and import them).
```
 
</details>

<details>
<summary><b>📝 Week 6: Files, Errors & OOP (part 1)</b></summary>

```
Study: Files & Exceptions (Osama Elzero, the videos after 85),
       Python OOP (classes, attributes, methods, inheritance)

1. Save the books to a file and load them when the program starts,
   so data survives restarts (a text file, or JSON if you want).
2. Handle errors (invalid input, missing file) using try / except,
   so the program never crashes.
3. Refactor the project to classes: Book, Member, Library.
4. Create a Person class (name, country, date of birth)
   with a method that calculates the age.
5. Apply inheritance: Member and Librarian inherit from Person.
```

</details>

<details>
<summary><b>📝 Week 7: OOP (part 2) & DSA (optional)</b></summary>


```
Study: Python OOP (polymorphism, abstraction), DSA (optional)
 
1. Create an abstract class `Item` with abstract methods (like get_info()).
2. Make Book and Magazine (or DVD) inherit from Item,
   each one implements get_info() in its own way.
3. The Library should work with any Item without caring about its type
   (polymorphism).
 
Optional (DSA, from the Grokking Algorithms book):
   - sort the books by title / year using selection sort
   - search for a book using binary search
```
</details>


<details>
<summary><b>📝 Week 8: Clean Code & Wrap up</b></summary>


```
Study: Clean Code (SOLID, KISS, DRY, YAGNI)
 
1. Single Responsibility: move saving/loading the file out of Library
   into its own class (e.g. Storage).
2. Remove repeated code (DRY) and any code you don't use (YAGNI).
3. Simplify any complicated function (KISS).
4. Write a README: what the project does, how to run it, and a short
   list of the principles you applied and where.
5. Push the project to your GitHub account.
```
 
</details>

### 🏆 Intermediate Project: Blog Platform with Roles

_A Django blog where readers, authors and editors each can do different things._

<details>
<summary><b>📝 Week 1: Database Design</b></summary>

```
Study: Database (Normalization, SQL Crash Course, MongoDB, ORM)

1. Design the blog database: User, Post, Comment, Tag, Like.
   Draw the ERD (one-to-many and many-to-many relations).
2. Apply normalization (up to 3NF) and write a few lines about
   what you changed and why.
3. Create the tables in SQLite or PostgreSQL using SQL
   and insert some sample data.
4. Write SQL queries for:
   - all posts of one author
   - each post with its comments count
   - the 3 most liked posts
   - all posts of a specific tag
5. Write a short note: how would this data look in MongoDB,
   and when would you choose SQL vs MongoDB?
```

</details>

<details>
<summary><b>📝 Week 2: Django Basics</b></summary>

```
Study: Intro to Django (What is Django, Architecture, Starts in Django)

1. Create the Django project and a `blog` app.
2. Create the Post model (title, content, author, created_at,
   status: draft / published) and add some posts from the admin panel.
3. Build the pages (urls + views + templates):
   posts list, post detail, create, update, delete.
4. In the README, explain how a request travels:
   urls -> view -> model -> template (MVT).
```

</details>

<details>
<summary><b>📝 Week 3: Django ORM</b></summary>

```
Study: Django ORM

1. Add Comment, Tag (many-to-many with Post) and Like models,
   and make sure they match your ERD from week 1.
2. Show comments, likes count and tags in the post detail page.
3. Posts list: filter by tag, search by title, sort by newest / most liked.
4. Use annotate / aggregate to calculate comments_count and likes_count,
   then build a "Top 5 most liked posts" page.
5. Fix the N+1 problem using select_related / prefetch_related
   and prove it (compare the number of queries before and after).
```

</details>

<details>
<summary><b>📝 Week 4: Auth, Roles & Design Pattern</b></summary>

```
Study: Authentication & Authorization, Design Patterns (creational)

1. Build register, login and logout.
2. Add 3 roles:
   - Reader: can comment and like
   - Author: can create posts, edit / delete only his own posts
   - Editor: can approve / reject posts and delete any post
3. New posts from an Author stay `draft` until an Editor publishes them.
   Readers see only published posts.
4. Protect your views (login required + permission checks)
   and return 403 when the user isn't allowed.
5. Use one creational pattern where it makes sense
   (e.g. a Factory that creates users by role) and explain it in the README.
6. Write the README and push the project to GitHub.
```

</details>

### 🏆 Advanced Project: URL Shortener API with Analytics

_A small but real API: create short links, redirect fast, count clicks in the background, and ship it with Docker._

> [!NOTE]
> **Web-RTC** and **AWS** have no mission. Watch Web-RTC to understand the idea, and use AWS as a bonus place to deploy.

<details>
<summary><b>🎯 Mission 1: API Foundation</b></summary>

```
Study: REST APIs & Postman, Django Rest Framework, Django Serializers

1. Create the Django project `shortener` and a `links` app.
2. Link model: original_url, short_code (unique), clicks (default 0),
   is_active, expires_at (nullable), created_at.
3. Build these endpoints using DRF + serializers:
   - POST   /api/links/        create a short link (generate the short_code)
   - GET    /api/links/        list links
   - GET    /api/links/<id>/   link details
   - DELETE /api/links/<id>/   delete a link
4. Validate in the serializer: valid URL, and expires_at can't be in the past.
5. Redirect endpoint: GET /<short_code> redirects to original_url
   and increases clicks by 1.
6. Test every endpoint in Postman and save them in a collection.
```

</details>

<details>
<summary><b>🎯 Mission 2: Auth & Tests</b></summary>

```
Study: JWT, Django Testing

1. Add register and login endpoints using JWT (access + refresh).
2. Add `owner` (FK to User) to Link:
   creating requires auth, and users can see / edit / delete only their links.
3. The redirect endpoint stays public.
4. Write tests for:
   - creating a link
   - the list returns only my links
   - I can't delete someone else's link
   - redirect works and increases clicks
   - expired / inactive links don't redirect
5. Update the Postman collection (auth + a description for each request).
```

</details>

<details>
<summary><b>🎯 Mission 3: Caching</b></summary>

```
Study: Caching & Redis

1. Install Redis and connect Django's cache to it.
2. Cache the redirect lookup (short_code -> original_url)
   so the database isn't hit on every click.
3. Update or clear the cache when a link is edited, deleted or deactivated.
4. Prove it works: compare the response time / number of DB queries
   before and after, and write the result in the README.
```

</details>

<details>
<summary><b>🎯 Mission 4: Live Click Counter</b></summary>

```
Study: Web Socket (Introduction, Django Channels)

1. Set up Django Channels with a Redis channel layer.
2. Create a WebSocket endpoint: ws/links/<short_code>/
3. Whenever someone opens the short link, broadcast the new
   click count to everyone connected to that endpoint.
4. Build a tiny HTML page that shows the counter updating live
   without refreshing.
```

</details>

<details>
<summary><b>🎯 Mission 5: Background Jobs</b></summary>

```
Study: Celery & Celery Beat

1. Set up Celery with Redis as the broker.
2. Create a Click model (link FK, clicked_at, ip, user_agent).
   Move saving the click into a Celery task so the redirect stays fast.
3. Use Celery Beat to run a daily task that deactivates
   links whose expires_at has passed.
```
